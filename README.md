# Рязань.Аренда

Веб-платформа аренды и продажи жилья: каталог с фильтрами, бронирование
с подтверждением владельцем, отзывы с модерацией, служба поддержки
и панель управления для персонала.

## Стек

Python 3.14 · Django 6.0 · SQLite · Pillow
Шаблоны Django + собственная дизайн-система на CSS-переменных, без JS-фреймворков.

## Запуск

```bash
python -m venv venv && source venv/bin/activate
pip install -r requirements.txt

python manage.py migrate
python manage.py createsuperuser
python manage.py runserver
```

| Адрес | Назначение |
|---|---|
| `/` | Сайт |
| `/crm/` | Панель персонала (`is_staff`) |
| `/admin/` | Django admin (`is_superuser`) |
| `/styleguide/` | Витрина компонентов |

Демо-данные: `python manage.py seed_demo` (флаг `--flush` очищает перед заливкой).

## Роли

Назначаются автоматически: после регистрации — **Арендатор**, после публикации
первого объявления — **Арендодатель**. Персонал определяется флагом `is_staff`
и получает доступ к `/crm/`.

## Бизнес-логика

**Объявление**

```
draft → pending → approved → публикуется
              ↘ rejected → правка → pending
```

Публично видны только объекты со статусом `approved` (менеджер
`Housing.objects.public()`). При отказе причина сохраняется и отправляется
автору уведомлением.

**Бронирование**

```
pending → confirmed → completed
       ↘ declined
       ↘ cancelled
```

Заявку создаёт гость, решение принимает владелец. Перед сохранением
проверяется: дата выезда позже заезда, дата не в прошлом, вместимость объекта
не превышена, объект не принадлежит самому гостю, даты не пересекаются
с уже подтверждёнными бронями. Сумма считается как цена × число ночей.

Перевод завершённых броней — командой по расписанию:

```bash
python manage.py mark_completed_bookings        # --dry-run для проверки
# cron: 0 3 * * * /path/venv/bin/python /path/manage.py mark_completed_bookings
```

**Отзывы**

Доступны только по собственному завершённому бронированию, один отзыв на бронь.
Публикуются после проверки персоналом; публикация пересчитывает рейтинг
и число отзывов объекта. Владелец может ответить на опубликованный отзыв.

**Поддержка**

Пользователь создаёт обращение, персонал отвечает через `/crm/tickets/`.
Сообщения от персонала помечаются автоматически. Чужое обращение недоступно.

## Маршруты

| URL | Доступ | Назначение |
|---|---|---|
| `/` · `/catalog/` · `/catalog/<pk>/` | все | Главная, каталог, страница объекта |
| `/service/` · `/help/` | все | О сервисе, справка |
| `/catalog/add/` · `/catalog/<pk>/edit\|submit\|delete/` | владелец | Управление объявлением |
| `/catalog/<pk>/book/` · `/booking/<pk>/<action>/` | вход | Бронирование и решения по нему |
| `/dashboard/` | вход | Обзор, брони, заявки, объявления, отзывы, избранное, календарь, доход, настройки |
| `/support/` · `/support/<pk>/` | вход | Обращения |
| `/reviews/booking/<pk>/` · `/reviews/<pk>/reply/` | вход | Отзыв и ответ |
| `/notifications/` | вход | Уведомления |
| `/crm/` | `is_staff` | Дашборд, модерация, объявления, брони, тикеты, отзывы, пользователи |
| `/accounts/` | все | Вход, регистрация, сброс пароля |

## Дизайн-система

| Файл | Содержимое |
|---|---|
| `tokens.css` | цвета, типографика, отступы, радиусы, тени, слои |
| `base.css` | сброс стилей, сетка, шапка, подвал |
| `components.css` | кнопки, поля, карточки, бейджи, модальные окна, вкладки, таблицы |
| `style.css` `catalog.css` `dashboard.css` `crm.css` `service.css` | страничные слои |
| `main.js` | вкладки, модальные окна, выпадающие меню, уведомления — через `data-`атрибуты |

Компоненты во всех состояниях — на `/styleguide/`.
Объявления без фотографии получают обложку из `static/img/covers/`,
выбираемую по идентификатору (шаблонный тег `cover_url`).

32 теста: переходы модерации, валидация бронирований (включая пересечение дат),
